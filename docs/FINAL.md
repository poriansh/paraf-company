# Implementation Notes

## Overview

در فرآیند پیاده‌سازی تسک، تلاش شد بخش‌های قابل پیاده‌سازی بر اساس API های موجود تکمیل شوند و ساختار پروژه با رعایت اصول React و معماری مناسب توسعه داده شود.

## Challenges

در حین توسعه، چند مورد باعث ایجاد محدودیت در تکمیل کامل برخی بخش‌ها شد:

- برخی API ها رفتار پایدار یا response structure کامل و مشخصی نداشتند.
- در بعضی endpoint ها خطاهای سمت API دریافت می‌شد که امکان تکمیل flow مربوطه را محدود می‌کرد.
- برای برخی بخش‌ها mapping دقیق بین داده‌های API و نیاز UI مشخص نبود.
- با توجه به ساختار SSR پروژه، هماهنگ‌سازی درخواست‌ها، مدیریت داده‌ها و اتصال آن‌ها به UI پیچیدگی بیشتری نسبت به حالت معمول داشت.

## Completed Parts

بخش‌هایی که contract مشخص داشتند و امکان تست کامل آن‌ها وجود داشت پیاده‌سازی شدند، شامل:

- ساختار کامپوننت‌ها
- مدیریت state و data flow
- اتصال بخش‌های قابل استفاده به API
- پیاده‌سازی UI بر اساس اطلاعات در دسترس

تنها بخشی که API و flow مشخص و شفاف‌تری داشت، بخش Authentication بود که به صورت کامل‌تر پیاده‌سازی شد.

در صورت ارزیابی عملکرد فنی، پیشنهاد می‌کنم بخش Authentication به عنوان نمونه اصلی بررسی شود، زیرا در این بخش امکان پیاده‌سازی دقیق‌تر بر اساس API contract موجود فراهم بود.

## Dashboard Notes

بخش Dashboard به دلیل وابستگی زیاد به تعداد زیادی endpoint و وجود پیچیدگی در تطبیق داده‌های API با UI، نیازمند بررسی و شفاف‌سازی بیشتری بود.

چالش اصلی در این بخش تعداد درخواست‌ها نبود، بلکه نبود یک contract کاملاً مشخص بین داده‌های دریافتی و ساختار مورد نیاز UI بود که باعث شد بخشی از زمان صرف تحلیل و تطبیق اطلاعات شود.

## Final Notes

با توجه به محدودیت‌های موجود در API و نبود مستندات کامل برای برخی بخش‌ها، بخشی از زمان توسعه صرف بررسی رفتار API ها و هماهنگ‌سازی آن‌ها با UI شد.

در صورتی که API ها دارای مستندات کامل‌تر و response contract مشخص‌تری باشند، امکان ارائه یک پیاده‌سازی کامل‌تر و نزدیک‌تر به محصول نهایی وجود خواهد داشت.

همچنین خوشحال می‌شوم در صورت نیاز، نمونه‌کارهای دیگری با سناریوهای کامل‌تر، UI مشخص‌تر و مستندات فنی کامل‌تر ارائه دهم تا توانایی‌های فنی و نحوه پیاده‌سازی بهتر ارزیابی شود.
